### [LOW] CODE-002: Блокирующий `time.sleep` в rate limit handler
- **Статус evidence:** CONFIRMED
- **Где найдено:** [github_api.py:L201-L215](file:///m:/Projects/Programs/GithubSearch/src/github_harvester/github_api.py#L201-L215)
- **Проблема:** При достижении лимита API функция `_wait_for_rate_limit` делает `time.sleep(1)` в цикле `while` (вплоть до 900 раз).
- **Почему это важно:** В многопоточной среде это заблокировало бы поток. Однако запросы к API выполняются в основном потоке (последовательно) перед многопоточной фазой клонирования (`download_repositories`), поэтому реального thread starvation здесь не возникает. Внутри цикла ежесекундно проверяется `should_cancel()`, что является хорошим тоном.
- **Минимальный fix:** Не требуется, работает корректно по задумке.
- **Нужно ли передать в другой audit:** нет.
